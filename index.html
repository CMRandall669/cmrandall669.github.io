How I work

I tend to operate as developer, analyst, and DevOps engineer at once — translating loose requirements into scoped work, then carrying it from data model to deployment. That means designing the schema and stored procedures, building the .NET APIs, workers, and RabbitMQ consumers, and delivering the React front end, plus owning the OpenShift CI/CD pipeline that ships it.

I look for the architectural problem behind the ticket — the client-side aggregation that should live on the server, the two verbose endpoints that should be one. And I implement AI-assisted workflows (Claude Code, Copilot) to move faster reducing the tedium of boilerplate setup and troubleshooting, while reviewing every generated change for correctness, security, and fit before it reaches production.
